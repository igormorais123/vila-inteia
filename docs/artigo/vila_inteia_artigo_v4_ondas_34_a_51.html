Resumo

Quarta parte da série Vila INTEIA. A versão v3 fechou o ciclo asimoviano conceitual. Esta v4 adiciona infraestrutura de produção que transforma a plataforma em um release 1.0 genuíno: (i) event-sourcing JSONL acoplado ao loop; (ii) meta-análise cross-runs; (iii) health endpoint agregado; (iv) export do grafo de conhecimento + visualizador force-directed sem D3; (v) Docker Compose stack com healthcheck e volumes; (vi) benchmark suite (12 operações com latências sub-ms); (vii) README Quickstart 3 passos; (viii) Prometheus /metrics exposition sem dependência externa; (ix) CHANGELOG Keep-a-Changelog + VERSION 1.0.0; (x) teste E2E Playwright; (xi) autenticação por API token + rate limit; (xii) backup CLI tarball; (xiii) notifier webhook Slack/Discord com anti-flood; (xiv) wiring end-to-end de auth e notifier no loop principal; (xv) matrix CI Python 3.11 + 3.12 cobrindo 16 suítes. Reportamos 387+ testes passing ao longo de 16 pull requests mergeados em sequência. Todas as 48 ondas do roadmap original estão materializadas.

1Observabilidade + event-sourcing (Ondas 34, 43)

O hook de event-sourcing (Onda 31) passou a ser acionado dentro de engine/simulacao.py:_executar_step_interno (Onda 34): cada step emite um Evento(tipo='step', payload={estado, n_conversas, n_insights}), cada Mule detectado emite Evento(tipo='mule') e cada recalibração automática emite Evento(tipo='calibracao'). O arquivo data/events/vila_events.jsonl é append-only e resistente a crash. Auditoria completa; nenhum evento é sobrescrito.

O endpoint GET /metrics (Onda 43) expõe 14 séries no formato exposition do Prometheus 0.0.4, sem depender de prometheus_client:

2Meta-análise cross-runs (Onda 35)

O módulo engine/meta_analise.py agrega N ExportRun (Onda 20) e calcula:

  • Distribuição agregada ponderada por run (cada run pesa igualmente, independentemente de seu comprimento)
  • Variância por estado: σ² cross-run, indicando reprodutibilidade
  • Estados universais (aparecem em 100% dos runs) vs raros (<50%)
  • Contagem de estados finais (convergência modal)
  • KL divergence pairwise mínima e máxima entre todos os pares

O output pode ser gerado em Markdown via relatorio_markdown(meta) para inclusão em relatórios.

3Health + Grafo export (Ondas 37-38)

O GET /api/v1/vila/health retorna snapshot de 8 subsistemas — rastreador, auto-calibrador, persistência, event log, grafo conhecimento, crenças, plataformas, MCP — com flag ok agregado. Se qualquer subsistema falha na importação ou stat call, fica marcado erro; os demais continuam operacionais.

O grafo de conhecimento (extraído dinamicamente de conversas, Ondas 6 + 23) agora tem endpoint GET /api/v1/grafo/export?limite_nos=N retornando JSON D3-compatible {nodes, links} + GET /api/v1/grafo/stats com top-10 nós por grau. O visualizador frontend/grafo.html implementa force-directed puro em SVG (sem dependência D3): 150 iterações de física (repulsão inverso-quadrático + atração linear via arestas + amortecimento 0.85), clamping aos limites do viewport.

5Release 1.0 (Ondas 43-45)

Arquivos VERSION (conteúdo: 1.0.0\n) e CHANGELOG.md (Keep-a-Changelog format) foram adicionados, formalizando o primeiro release estável. O MANIFEST.md (Onda 39) serve como tabela de índice operacional.

O teste E2E Playwright (tests/e2e_playwright.py) sobe o servidor live local, navega para /cockpit.html em Chromium headless, valida elementos essenciais da DOM, testa endpoint /health (≥8 subsistemas) e /metrics (Prometheus format). Auto-skip gracioso se Playwright não instalado, permitindo rodar em CI mínimo.

6Segurança: auth + rate limit (Onda 46)

O engine/auth.py implementa middleware FastAPI que:

  1. Valida X-API-Token contra VILA_API_TOKEN; 401 se diverge (quando token configurado)
  2. Aplica rate limit por IP: janela deslizante 1 minuto, default 120 rpm (VILA_RATE_LIMIT_PER_MIN)
  3. Excluí automaticamente /docs, /openapi.json, /redoc, /api/v1/vila/health, /metrics — garante que observabilidade permaneça acessível mesmo quando auth está ativo
  4. Injeta headers X-RateLimit-Remaining + X-RateLimit-Limit em respostas bem-sucedidas

Em dev mode (VILA_API_TOKEN vazio) o auth é desabilitado automaticamente — mantém quickstart 3 passos sem fricção.

7Backup + webhook notifier (Ondas 47-48)

O scripts/vila_backup.py tem três subcomandos:

vila_backup.py dump --arquivo vila-backup.tar.gz --url http://localhost:8100
vila_backup.py list --arquivo vila-backup.tar.gz
vila_backup.py restore --arquivo vila-backup.tar.gz --apenas data/events/

O dump captura todos os arquivos persistentes (data/events/, data/vila_inteia_default/, data/colmeia_estado.json, data/backtest/) mais o estado ao vivo (se URL fornecida: trajetória + divergência + health + grafo JSON serializado como live_state.json). O restore aceita filtro de prefixo para restaurações seletivas.

O engine/notifier.py envia POSTs HTTP a webhook compatível Slack/Discord/generic:

  • notificar_mule(mule, step) — emoji 🚨, texto com z-score + descrição
  • notificar_recomendacao_critica(estado, destino, n_mules) — emoji ⚠️, resumo urgência
  • notificar_calibracao(step, ganho_pct) — emoji ✓, ganho perplexity

Anti-flood interno: mesmo tipo de notificação não re-envia em intervalo <30s. Histórico das últimas 100 notificações preservado em memória.

8Wiring + CI matrix (Ondas 49-50)

O main.py em serve e live agora monta o middleware auth (importação condicional, falha silenciosa se módulo indisponível). O engine/simulacao.py chama NOTIFIER_GLOBAL.notificar_mule e notificar_calibracao dentro dos hooks respectivos.

O GitHub Actions passa a rodar matrix Python 3.11 + 3.12, cobrindo 16 suítes de teste (game theory, opinion dynamics, sim avançada, psico-história, crença, proveniência, grafo conhecimento, plataformas, Ondas 5-9 integrado, detector estado, 13-16, 17-19, replay, 22-24, 25-27, 28-30, event log, meta-análise, 37-39, 40-42, 43-45, 46-48). Total: 387+ casos passing por matriz.

10Conclusão

A Vila INTEIA v1.0 entrega uma plataforma completa: simulação multi-agente fundamentada em teoria dos jogos + dinâmica de opiniões + psico-história computacional, com observabilidade, persistência, autenticação, backup, notificações, CI robusto, artigos acadêmicos e ferramentas CLI. Todas as direções originalmente planejadas estão materializadas.

Próximas direções ficam a critério de demanda operacional: escala Ray distribuído (Onda 9 esqueleto → implementação completa), integração com LLMs reais (OmniRoute/Anthropic chaves), publicação open-source, fine-tuning do classificador heurístico via grid search em runs acumuladas.
